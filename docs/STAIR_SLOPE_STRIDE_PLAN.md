# 계단·경사로 오인식에 따른 보폭 축소 수정 계획

작성일: 2026-10-07
상태: 서버 측 `fusion-v4` revision 6 구현 완료. 기존 Claude의 미커밋 revision 5를 기반으로 Health 초기 보폭과 미확정 수직 이동 상태를 연결했다. 실제 경로 비교 및 현장 적용은 검증 대기다.

추가 설계: [Health 기반 개인 보폭 서버 계획](HEALTH_STRIDE_SERVER_PLAN.md), [Xcode 앱 수정 프롬프트](IOS_HEALTH_STRIDE_PROMPT.md). 사용자별 초기 보폭, 미확정 구간의 대체값, 세션별 재현성은 이 추가 설계를 따른다. 계단 확정 및 소급 보정 문제는 본 문서와 함께 수정한다.

## 1. 목표와 확인된 원인

목표는 경사로의 높이 변화를 계단으로 오인해 수평 이동거리가 지속적으로 짧아지는 문제를 줄이면서 실제 계단의 이동거리 과대 추정을 막는 것이다. 실시간 FORWARD와 사후 FINAL을 별도로 검증한다.

현재 로컬 설정은 `ACTIVE_FUSION_VERSION=fusion-v4`다. 실행 중인 서버의 배포 코드와 설정까지 확인한 것은 아니다.

- `fusion-v4.engine.ts`의 `applyStep()`은 기압 기반 수직 속도 절댓값이 `0.13m/s` 이상이면 수직 이동으로 취급한다. 추정에는 최근 4초의 기압 관측을 사용한다.
- 계단으로 분류하면 단순한 최대 보폭 제한이 아니라 **걸음당 수평 이동거리를 `stairTreadM=0.30m`로 대체**한다. 예를 들어 실제 수평 보폭이 0.70m인 구간에서 100걸음을 그렇게 처리하면 GPS 등 보정 전 누락 거리는 40m다.
- 일반 보행에는 별도로 `strideMinM=0.35`, `strideMaxM=1.1` 범위 제한이 있다. 이 상한을 올리는 것만으로 계단 분기의 0.30m 고정 문제는 해결되지 않는다.

## 2. Claude 작업에서 이어받을 부분

확인한 기록: 프로젝트별 Claude 메모 `fusion-v4-slope-understride.md`와 `fusion-stabilization-roadmap.md`. 기록의 revision 5 변경이 실제 작업 디렉터리의 diff와 일치한다.

| 기존 작업 | 이어받는 방법 |
| --- | --- |
| 같은 방향으로 5m 이상 높이가 변하고 경로 직진도가 0.7 이상이면 경사로로 재분류 | 경사로를 지지하는 보조 증거로 재사용. 계단 여부를 결정하는 유일한 규칙으로 쓰지 않음 |
| 경사 구간의 보수계 거리로 별도 보폭 보정 | 평지/경사 보폭을 분리하는 구조를 유지하고 혼합 구간 표본 처리를 보강 |
| 처음 계단으로 처리한 걸음의 길이와 현재 위치를 소급 보정 | 걸음 이력 재사용. GPS 보정과의 중복 및 공분산 일관성을 검증한 뒤 보정 방식 결정 |
| 감지 걸음 수와 보수계 걸음 수가 불일치하면 보정 표본 보류 | 유지. 센서 누락·재시작·지연 수신에서도 검증 |
| `slopeSteps`, 스무더 분산, 진단 정보 추가 | 유지하고 분류 근거·변경 시점·거리 수정량을 추가 |

Claude 메모에는 혜인관→주차장 경사로→북악관 경로가 약 80m 짧게 끝났으며, 실제 자료에서 수직 속도·걸음당 높이 변화·규칙성이 계단과 경사로 사이에 겹쳤다고 기록되어 있다. 이번 검토에서 해당 원자료를 다시 분석한 수치는 아니므로 재현 단계에서 확인한다. 기압 변화나 층수 변화 하나만으로 둘을 구분한다는 전제는 두지 않는다.

현재 수정본의 관련 단위 테스트 10개와 backend 타입 검사는 통과했다. 실제 세션 replay, `default`/`sim` bench 및 Lab 비교는 이번에 실행하지 않았다. Claude 기록에도 비교 검증이 후속 작업으로 남아 있다.

## 3. revision 5에서 아직 해결되지 않은 문제

1. **짧은 경사로:** 높이 변화가 5m에 못 미치면 경사로 복원 조건에 도달하지 않는다.
2. **곡선·회전 경사로:** 직진도 조건 때문에 계단으로 남을 수 있다. 나선형 주차장 램프가 대표적인 검증 대상이다.
3. **긴 직선 계단:** 높이 차가 5m를 넘으면 반대로 경사로로 분류될 수 있다. 기존 계단 테스트가 20초에서 12초로 짧아졌으므로 원래 길이의 사례도 회귀 테스트로 복원한다.
4. **판정 지연:** 수직 속도 0.2m/s라면 5m 누적에 약 25초가 필요하다. 마지막 위치가 복원되어도 이미 송출한 실시간 경로가 정확했다는 뜻은 아니다.
5. **소급 보정 일관성:** `stairsToSlope()`는 과거 보폭 차이를 현재 위치에 더한다. `reckonedFrom`은 방향 fitting·재앵커 시 갱신되지만 일반 GPS 채택 시에는 갱신되지 않는다. 이미 GPS가 보정한 거리까지 다시 더하는지 재현 테스트가 필요하다. 단순히 모든 GPS마다 시작점을 옮기는 해결도 누락 보정을 잃을 수 있다.
6. **분류의 파급:** `stairs`는 보폭 외에 실내 계단 앵커에도 쓰인다. 새 분류는 앵커·지면 접촉·높이 기준 추정까지 일관되게 연결해야 한다.

## 4. 권장 설계

### 4.1 수직 이동 감지와 계단 확정을 분리

내부 이동 상태를 `LEVEL`, `VERTICAL_UNKNOWN`, `STAIRS`, `SLOPE`로 표현한다. 센서가 부족하다는 이유로 평지 또는 계단을 확정하지 않도록 관측 품질도 별도로 보관한다.

- 기압 변화는 우선 `VERTICAL_UNKNOWN`을 만든다. 이 조건만으로 0.30m를 적용하지 않는다.
- 높이 변화, 걸음 수 일치, 회전 패턴, 관측 지속 시간, 센서 공백을 함께 기록한다. 각 특징의 분리 성능은 라벨이 있는 실제 구간에서 확인한다.
- 직진도는 긴 직선 경사로의 보조 증거다. 낮은 직진도를 곧바로 계단 증거로 뒤집지 않는다.
- 진입·이탈에 별도 지속 조건을 두고, 수직 속도가 임계값 주변을 오갈 때 상태가 매 걸음 바뀌지 않도록 한다. 시간·신뢰도 기준은 설정에 포함한다.
- 증거가 충돌하거나 센서가 끊기면 `VERTICAL_UNKNOWN`으로 돌아간다. 긴 직선 계단과 짧은 경사로처럼 센서만으로 모호한 사례는 모호한 상태를 허용한다.

### 4.2 분류와 거리 추정을 분리

걸음마다 `baseLength`, `appliedLength`, `lengthVariance`, `terrainMode`, `reason`을 남긴다. 분류 결과가 보폭 원자료를 덮어쓰지 않게 한다.

| 상태 | 초기 구현의 보폭 정책 |
| --- | --- |
| LEVEL | 현재 세션의 검증된 평지 보폭을 우선하며, 초기에는 유효한 Health 개인 보폭, 없으면 0.72m 사용 |
| SLOPE | 해당 경사 구간의 유효한 보수계 표본으로 추정. 부족하면 세션 평지 보폭→Health 개인 보폭→0.72m 순으로 대체 |
| VERTICAL_UNKNOWN | 세션 평지 보폭→Health 개인 보폭→0.72m 순으로 임시 사용하고 거리 불확실성을 확대. 0.30m 강제 대체 금지 |
| STAIRS | 충분한 계단 근거가 있을 때만 계단 수평 보폭 모델 사용. 0.30m는 초기 사전값으로 취급하고 불확실성을 유지 |

이 정책은 불확실한 실제 계단에서는 거리를 길게 추정할 수 있다. 따라서 경사로 개선만 보고 출시하지 않고 계단 오차를 별도 통과 조건으로 둔다. 분리 가능한 증거가 부족해 두 조건을 함께 충족하지 못하면 지도 보조 또는 추가 수집을 다음 필수 단계로 올린다.

신뢰도에 따른 두 보폭의 가중 혼합은 후속 후보로 둔다. 학습·보정하지 않은 숫자를 계단 확률처럼 사용하지 않는다. 또한 보수계의 경사 거리 의미를 확인하기 전에는 높이 변화로 수평 투영을 추가해 거리를 두 번 축소하지 않는다.

### 4.3 보폭 학습 오염과 구간 경계 처리

- 기존 걸음 수 일치 검사와 누적 카운터 보호를 유지한다.
- 계단/경사/평지/미확정 상태가 섞인 보수계 묶음은 초기 구현에서 학습 표본에서 제외한다. 감지된 걸음 비율만으로 거리를 나누는 방식은 먼저 검증하지 않고 도입하지 않는다.
- 센서 segment 변경, 기압 재기준화, 긴 공백, 오르막↔내리막 전환 시 분류 창과 보류 표본을 정리한다.
- 미확정 걸음은 평지 보폭 학습에 넣지 않는다. 재분류 후 사용할 수 있는 표본은 해당 구간에 완전히 포함된 경우로 한정한다.
- 달리기의 `strideMaxM=1.1` 제한은 별도 이슈로 남긴다. 이번 실험에서는 걷기 자료와 섞어 효과를 판단하지 않는다.

### 4.4 실시간 보정과 사후 보정

최종 경로는 재분류된 걸음 길이로 스무더를 다시 실행한다. 실시간은 과거 보폭 차이를 현재 위치에 무조건 더하는 방식 대신, **제한된 최근 구간의 상태 체크포인트와 센서 관측을 보관하고 해당 구간의 예측·GPS 업데이트를 다시 계산하는 방식**을 우선 검토·구현한다.

- 버퍼 길이는 분류 지연 분포와 처리 비용을 측정해 결정한다. 긴 지연을 무제한 보관하지 않는다.
- 재계산은 걸음·방향 전환·GPS 보정·재앵커·공분산을 함께 복원한다. 같은 분류를 다시 적용해도 두 번 보정되지 않아야 한다.
- 재계산 중 동일한 분류 전환 이벤트가 재귀적으로 발생하지 않도록 확정된 구간 결정과 상태 재생 단계를 분리한다.
- 버퍼 밖의 과거는 FINAL에서 처리하고 실시간에 복구되지 않은 구간을 진단 정보에 남긴다.
- 이미 송출한 점은 현재 서비스가 지원하는 방식에 맞춰 취급한다. 과거 점 교체가 필요하면 별도 수정 이벤트와 소비 측 처리를 설계하며, 현재 위치 보정만으로 과거 FORWARD까지 고쳐졌다고 보고하지 않는다.

계단 앵커에는 확정된 `STAIRS`만 사용한다. 경사/미확정 구간의 지면 접촉 제외 정책은 우선 revision 5의 보수적인 처리를 유지하고, 야외 경사로와 지하 주차장 램프의 높이 오차를 각각 검증한다.

### 4.5 지도 보조는 독립된 후속 단계

편집기에는 `stairs`/`ramp` 도로 속성이 있지만 현재 fusion `Observation`에는 도로 유형을 직접 전달하는 계약이 없다. 이미 사용할 수 있는 센서 입력처럼 가정하지 않는다.

필요하면 도로 공간 조회, 지도 버전 고정, 수평 위치 불확실성, 층·높이 호환성을 포함한 입력 계약을 추가한다. 가까운 계단이 있다는 이유만으로 계단 확정은 하지 않는다. 도로 정보가 없거나 상충할 때도 센서 경로가 동작해야 한다.

## 5. 실행 순서와 수정 대상

1. **비교 기준 고정:** 현재 revision 5의 미커밋 diff와 설정을 보존한다. revision 4의 기존 run과 revision 5 비교 run을 식별하고 코드·설정·지도 버전 및 입력 자료를 기록한다. 기존 사용자 변경은 덮어쓰지 않는다.
2. **실패 사례 재현:** 현재 긴 직선 경사로 테스트를 유지하고 짧은/곡선 경사로, 긴 직선 계단, GPS 보정 후 재분류 사례를 먼저 추가한다. 실제 문제 세션의 구간 라벨과 센서 유효률을 확인한다.
3. **분류·보폭 분리:** `fusion-state-v4.ts`, `fusion-v4.engine.ts`, `fusion.config.ts`를 수정한다. 함수가 커지면 `fusion-v4.locomotion.ts`로 분류와 보폭 정책을 분리한다.
4. **실시간·스무더 정합:** `fusion-v4.engine.ts`, `fusion-v4.smoother.ts`에서 재분류, 분산, 재계산을 연결한다. 실내 계단 앵커와 지면 접촉 경로도 함께 수정한다.
5. **관측 가능성:** `fusion.diagnostics.ts`, `fusion.metrics.ts`, `fusion.algorithms.ts`에 미확정 걸음 수, 모드 전환 근거·시점, 보폭 원래 값/적용 값, 누적 축소 거리, 재분류 지연, 실시간 보정량을 추가한다. 최종 상태만으로 당시 판단을 덮어쓰지 않는다.
6. **검증 후 적용:** 다음 엔진 revision으로 구분하고 명시적 variant로 비교한다. 실시간 기본 적용과 기존 세션 게시 재처리는 검증 결과에 따라 순서대로 진행한다.

## 6. 검증 계획과 완료 기준

| 검증 사례 | 확인할 사항 |
| --- | --- |
| 평지, 짧고 긴 오르막·내리막, 5m 미만 경사로 | 높이 변화만으로 0.30m 고정이 발동하지 않음, 거리 누락 감소 |
| 곡선·지그재그·나선형 경사로 | 직진도 부족만으로 계단 확정하지 않음 |
| 한 층 계단, U자/나선형 계단, 긴 직선 계단 | 실제 계단 거리 과대 추정 및 건물 밖 이탈 악화 방지 |
| 경사→평지→계단, 짧은 참, 중간 정지 | 상태 떨림과 보폭 학습 오염 방지 |
| 엘리베이터·에스컬레이터에서 소수 걸음 | 큰 높이 변화가 일반 보행 거리로 바뀌지 않음 |
| 기압 노이즈·결측·재시작, 자세 변경, 보수계 지연/불일치 | 잘못된 구간 연결 방지, 불확실성 증가, 유한한 출력 |
| GPS 채택/거부·재앵커·방향 재추정 뒤 재분류 | 중복 보정 없음, 체크포인트 재계산의 상태·공분산 정합 |
| 실시간 수신 순서와 센서 시간 순서 replay | 각 모드의 결정성, 지연 관측 처리, FORWARD와 FINAL 별도 성능 |

테스트는 `fusion-v4.engine.test.ts`를 중심으로 추가하고 pipeline·pedometer·terrain 관련 회귀 및 전체 backend 테스트를 실행한다. 기존 golden 검증은 의도한 v4 출력 변경을 실패로만 취급하지 않고, 기존 버전의 불변성과 동일 revision 재현성을 분리해 확인한다.

실제 세션은 혜인관→주차장 경사로→북악관, 본관–문예관 경사로 및 실제 계단 구간을 우선 비교한다. 각 구간의 시작/끝 기준점과 길이를 독립적으로 확인한다. GPS나 보수계 자체를 정답으로 삼지 않는다. 파라미터 조정용 세션과 최종 확인용 세션을 분리한다.

초기 수치 목표는 다음과 같으며, 실제 정답 자료의 정확도를 확인한 뒤 평가 전에 확정한다.

- 정답이 있는 합성 경사로: 구간 이동거리 상대 오차 10% 이하. 전체 경로뿐 아니라 경사로 진입 직후부터 FORWARD 오차도 집계.
- 실제 문제 경사로: 기준 대비 거리 부족 오차 50% 이상 감소. 끝점 오차와 XY P95도 함께 보고.
- 평지·계단: 거리 오차와 기준점 XY P95의 악화가 각각 10% 또는 1m 중 큰 허용폭 이내. 이를 넘는 구간은 원인 해결 전 적용 보류.
- 분류 전환 때문에 추가되는 실시간 위치 점프는 재생 실험에서 별도로 측정하고, 초기 목표 2m 이내. 정당한 GPS 재앵커 점프와 구분하며, 단순 표시 보간으로 추정 오류를 감추지 않음.
- 동일 입력·설정의 결과가 결정적이고, 재분류를 반복해도 거리가 중복 증가하지 않음.

`default`와 `sim` bench는 반복 주행의 일관성을 보는 보조 평가다. 독립 기준점 기반 정확도 검증을 대체하지 않는다. 비교 실험은 항상 `--variant=slope-rev5` 또는 다음 revision의 명시적 이름을 사용하고 `--publish` 없이 실행한다. variant 없는 최신 run이 대표 경로 계산에 선택될 수 있기 때문이다. baseline은 revision·run ID가 확인된 고정 결과를 사용한다.

## 7. 적용과 되돌리기

검증을 통과하면 먼저 신규 세션에서 제한적으로 적용하고, 이후 선정한 기존 세션부터 재처리한다. 비교용 run과 이전 게시 결과의 식별자를 보존한다. 실패 시 이전 코드/revision·설정으로 복귀하고 해당 기준 run을 복원하는 절차를 준비한다. 원본 센서 자료는 수정하지 않는다.

완료란 긴 직선 경사로 테스트 통과에 그치지 않는다. 짧고 굽은 경사로의 축소가 개선되고 실제 계단이 악화되지 않으며, 실시간과 사후 결과 모두 독립 기준점으로 확인된 상태를 뜻한다.
